```markdown
### 边界场景与变体
- 边界值、长度限制、特殊字符规则、必填规则、格式规则等不得根据通用经验或模板示例自行假设，必须以实际需求文档、页面行为、前端校验、后端代码或数据库约束为依据；若无法确认，应标记“待确认”，不得编造具体值。
- 以上规则适用于测试点提取及测试用例编写两个阶段。测试点阶段需先识别是否存在空值、边界值、特殊字符、必填、格式等校验需求；测试用例阶段再根据已确认的实际规则填写具体测试数据与预期结果。

| 变体 | 输入 | 预期结果 |
|-----------|-------|-----------------|
| 空值/空输入 | 根据字段实际情况填写 | 根据实际校验规则填写 |
| 边界值 | 根据前端/后端规定填写 | 根据实际规则填写 |
| 特殊字符 | 根据实际允许/禁止字符填写 | 根据实际规则填写 |
```

### 完整用例工作簿标准结构（不得随意修改或增减）
完整功能测试用例工作簿按以下顺序组织：

1. 使用说明：必需；
2. 测试用例：必需；
3. 追溯矩阵：必需；
4. 规则：存在已确认业务规则时生成；
5. 数据准备：存在共享账号、角色、菜单、部门或测试数据集时生成；
6. 待确认清单：存在会影响测试数据或预期结果的待确认事项时生成；
7. 测试点：输入文件包含测试点，或本次生成、完善了测试点时保留。

只有用户明确要求生成单一简单表格，且不要求追溯矩阵、覆盖统计和工作簿说明时，才可以省略“使用说明”工作表。

不得在没有用户明确要求的情况下，省略完整功能测试用例工作簿中的“使用说明”工作表。

#### 用例工作簿：“使用说明”Sheet

“使用说明”工作表用于说明当前工作簿的用途、来源、规模、覆盖情况及遗留问题。

“使用说明”工作表必须放在工作簿第一个位置。
建议使用两列表格：

| 项目 | 内容 |
| --- | --- |
| 测试范围 | 本次覆盖的模块和主要功能 |
| 测试用例总数 | “测试用例”工作表中的有效用例数量 |
| P0/P1/P2/P3用例数 | 按优先级统计，例如：P0：10，P1：20，P2：15，P3：5 |
| 测试点总数 | 最终测试点数量 |
| 本次范围外测试点 | 不属于当前交付物的测试类型或执行范围 |
| 已覆盖/未覆盖测试点数 | 例如：已覆盖109，未覆盖0 |
| 测试点覆盖率 | 已覆盖测试点数 ÷ 适用测试点总数 × 100% |
| 孤儿用例数 | 没有有效测试点来源的用例数量 |
| 遗留问题 | 未覆盖测试点、孤儿用例、待确认规则及其他限制 |

填写要求：

- 所有数量必须根据最终工作簿的实际内容计算，不得填写估算值；
- 同一用例关联多个测试点时，用例数只计算一次；
- 同一测试点关联多条用例时，测试点覆盖数只计算一次；
- 本次范围外测试点不计入覆盖率分母；
- 范围外、未覆盖或孤儿数量大于0时，必须在“遗留问题”中列出对应ID及原因；
- 统计结果必须与“测试用例”和“追溯矩阵”工作表保持一致。

“本次范围外”只用于不属于当前交付类型的专项测试，例如接口、性能、安全、兼容性或故障注入测试。规则不明确的测试点应标记为“待确认”，不能标记为“本次范围外”。


#### 用例工作簿：规则Sheet
- “规则”Sheet只记录已经确认、可以直接决定测试数据或预期结果的规则。不得写入其他内容
- 规则编号格式为 R[三位序号]，例如 R001、R002、R003。
- 一条来源内容包含多个可以独立引用的规则时，应拆分为多个规则编号。例如：角色名称不能为空，最长30个字符，并且具有唯一性。应拆分为三条规则
- "来源"列写入测试点文件的“规则说明”Sheet中对应的规则ID

## 功能测试用例模板

用于测试业务逻辑和功能特性。

```markdown

## 完整测试用例列（严禁随意修改、增加或删除）
- 用例编号
- 模块/功能
- 用例标题
- 测试方法
- 优先级
- 前置条件
- 测试数据
- 测试步骤
- 预期结果
- 后置条件
- 规则依据
- 实际结果
- 是否通过
- 备注

## Case-[MODULE]-NNN: [功能] - [场景]

**优先级:** P[0-3]
**类型:** 功能
**模块:** [功能/模块名称]

### 用例编号规则

测试用例编号格式：

Case-[模块缩写]-[三位序号]

示例：
- 登录模块：Case-LOGIN-001
- 用户管理：Case-USER-001
- 角色管理：Case-ROLE-001

模块缩写应与测试点ID中的模块缩写保持一致。
同一模块内序号从001开始递增，并保持唯一。

### 测试数据命名规则

测试数据应使用统一、可读、可追踪的命名方式。

#### 命名格式

`test_[角色或用途]_[三位序号]`

#### 示例

- 管理员用户：`test_admin_001`
- 普通用户：`test_user_001`
- 停用用户：`test_disabled_001`
- 角色测试数据：`test_role_001`
- 删除场景数据：`test_delete_001`

#### 命名要求

- 使用小写英文单词；
- 单词之间统一使用下划线 `_` 分隔；
- 序号统一使用三位数字，从 `001` 开始；
- 同一角色或用途下序号递增，并保持唯一；
- 名称应能体现测试数据的角色或用途；
- 不使用无意义名称，如 `test1`、`aaa`、`user123`；
- 若测试数据仅用于单条用例，可结合场景增加用途标识，但应保持简洁。

Agent 生成测试数据时，应优先根据“角色”或“测试用途”命名；若无法明确分类，可使用 `test_data_[三位序号]` 作为兜底格式。

### 测试目标
验证当[场景]发生时，[功能]的行为是否正确

### 前置条件
- 用户已以[角色]身份登录
- [功能前置条件]
- 测试数据: [数据集]

### 测试步骤

1. 导航至[页面/功能]
   **预期结果:** [页面正确加载]

2. 执行[操作]
   **输入:** [测试数据]
   **预期结果:** [系统响应]

3. 验证[结果]
   **预期结果:** [成功标准]

### 预期结果
- 测试步骤与预期结果必须使用相同序号且数量一致。
- 每条预期只描述对应步骤产生的可观察结果。
- 新增、修改、删除、查询等不同操作不得复用不适用的措辞。尽量带入具体数据，例如删除操作：成功删除test_user_008。

### 规则依据
- 必须填写具体规则编号。
- 一个用例涉及多条规则时，使用顿号或逗号分隔，如 R03、R08。

### 实际结果，是否通过。备注
- 这三列为空，由QA填写

### 补充校验
- 根据实际需求判断是否需要边界值、空值、必填、格式、特殊字符等校验
- 根据实际业务判断是否需要异常流程、权限、状态冲突等场景
- 无对应规则时不强制生成


### 边界测试（可选变体检查）

- 最小值-1: [根据实际边界规则判断是否适用]
- 最小值+1: [根据实际边界规则判断是否适用]
- 最大值: [根据实际边界规则判断是否适用]
- 最大值-1: [根据实际边界规则判断是否适用]
- 最大值+1: [根据实际边界规则判断是否适用]


### 异常测试（可选变体检查）
- Null/空值: [根据字段是否允许为空判断]
- 超长值: [根据实际字段类型及业务场景设计，例如字符串字段输入远超正常长度的数据]
- 无效输入: [根据字段格式、类型、取值范围等规则设计]
- 未授权访问: [根据功能权限要求判断]
```

### 用例编号规则

测试用例编号格式：

```markdown
- 登录模块：API-LOGIN-001

### 当项目无正式接口文档时：

- 测试点阶段优先根据页面功能、业务规则、前后端行为提取接口测试场景。
- 生成接口测试用例时，若请求方法、接口路径、Headers、参数位置、业务码、响应结构等尚未确认，应使用“待抓包确认”或“待代码确认”占位，不得自行编造。
- 测试人员通过浏览器 Network、Postman/Fiddler 抓包或后端代码确认真实接口信息后，再补全详细接口用例。

### 测试目标
验证[接口]在[场景]下，请求处理、响应结果及业务数据是否正确。

### 前置条件
- [接口服务正常运行]
- [所需账号/Token 已准备]
- [前置测试数据已存在]
- [其他业务前置条件]

### 请求数据


### 测试步骤

1. 按照测试数据发送接口请求
   **预期结果:** [请求能够被系统正确接收并处理]

2. 验证 HTTP 响应
   **预期结果:** 
   - HTTP 状态码符合接口实际设计
   - 响应格式正确

3. 验证响应体
   **预期结果:** 
   - 业务状态码符合预期
   - 返回字段及字段值正确
   - 错误信息与实际业务规则一致

4. 验证业务结果
   **预期结果:**
   - 新增/修改/删除/查询结果符合预期
   - 必要时通过查询接口或数据库进行二次校验

### 参数校验
- 必填参数: [根据接口规则判断]
- 空值/Null: [根据字段规则判断]
- 边界值: [根据实际边界规则判断]
- 无效值: [根据字段格式、类型、枚举范围等规则判断]

### 权限与认证
- 未携带 Token: [根据接口认证规则判断]
- Token 无效/过期: [根据接口认证规则判断]
- 无权限用户访问: [根据接口权限规则判断]
```

```markdown
### 集成点

- [ ] 相关接口行为未发生异常变化
```

## 优先级定义

| 优先级 | 描述 | 执行时机 |
|----------|-------------|-------------|
| P0 | 关键路径，阻塞发布 | 每次构建 |
| P1 | 主要功能，影响较大 | 每日/每周 |
| P2 | 标准功能，中等影响 | 每周/发布前 |
| P3 | 次要功能，影响较低 | 仅发布前 |
